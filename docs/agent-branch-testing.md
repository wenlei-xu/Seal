# Seal 创作助手开发与试用

当前助手基于官方 pi SDK，会话和历史由宿主保存，浏览器通过本地 API 读取状态与发送消息。画布和独立剪辑工程复用同一套助手界面。

## 安装与配置

完整包、开发预览和随包运行端的区别见 [桌面开发](desktop-local-development.md) 与 [桌面发布](desktop-release.md)。应用名为 `Seal.exe`；仅复制 exe 不能运行助手，应保留整个完整包目录。

在“模型配置”中配置支持工具调用的文字模型，并选择助手模型。当前仓库不要求使用某个供应商账号，也不携带用户凭据。测试前保存工程，并使用独立的测试工作区。

## 试用方式

- 在画布中选择对象，让助手读取、创建节点、修改标题或连接节点。
- 在剪辑工程中引用当前工程素材，让助手读取时间线、调整片段或制作候选场景。
- 在输入框使用 `/` 或技能按钮指定已启用的技能；在 Skill Hub 中管理技能文件。
- 对话中能实时看到工具执行状态；一轮结束后可查看执行记录、改动与生成提议。
- 付费素材生成仍需确认已有提议，不以文字回复代替实际任务完成状态。

## 零模型界面验收

以下入口使用模拟事件和数据，不访问真实模型或用户工程：

```powershell
cd web
bun test/fixtures/assistant-streaming-server.ts
```

打开输出的回环地址，可以检查流式 Markdown、工具状态、200 回合历史、明暗主题及停止操作。

如需验证真实工程操作，再用本地测试工程完成一轮小范围改动和读回。只有需要验证真实模型调用时才使用自己配置的渠道，并核对供应商费用。问题报告应包含 Seal 版本或提交、系统、模型、复现步骤和脱敏截图。
